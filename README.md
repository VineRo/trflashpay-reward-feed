## 正確性邊界

`catalog.json` 列出 App 的 20 個內建付款來源。未核對的卡片會明確列為 pending，App 不會使用其內建範例回饋率當作銀行當期優惠。新資料有效期 36 小時；快取過期時也回到待核對狀態。使用者獨立 ID 的自訂卡片仍保留自訂規則。

來源清單現已登錄 20 個內建來源的官方頁面（中信兩卡共享快照）。登錄頁面不代表已完成回饋解析；可讀取數、失敗原因與待核對項目會列在 status.json。CUBE 舊 2024 活動頁已移除，改用當期產品頁。

目前有十二個卡片專用解析器（涵蓋七家銀行）：

- 中信 LINE Pay 信用卡：由一般消費表格與重複敘述交叉核對回饋率、有效期間及既有資格／取整條款。
- 中信 LINE Pay 簽帳金融卡：使用簽帳金融卡欄位及其自身有效期間，不套用信用卡國外實體商店加碼。
- 富邦 J：讀取國內及其他海外一般消費欄位，與未達條件時的回饋率分開辨識；不使用日韓泰旅遊或新戶活動最高回饋。重複的桌面／行動版段落須一致，J Cash／J Points 與資格仍待確認。
- 玉山 U Bear：分別擷取基本、網路加碼、總回饋率與每期加碼上限，檢查合計一致，避免誤取新戶或數位訂閱的廣告最高數字。

- 聯邦吉鶴：民國日期轉換，核對國內一般消費與新臺幣請款，不混入日本、名店與新戶加碼。
- 玉山 Unicard：僅擷取一般消費基本方案，核對電子帳單與成功自扣，不使用指定方案最高值。
- 富邦 Costco：分離店外一般消費好多金與店內、加油及交通活動，依店外活動期限撤回過期資料。
- 永豐 SPORT：核對一般基本回饋及電子帳單加碼合計，不將運動達標或指定支付加碼當作無條件回饋。

- 台新 Richart（原 @GoGo）：僅擷取一般基本回饋，核對原卡納入範圍，不套用切換方案或保費最高值。
- Richart Mastercard 簽帳金融卡：不與晶片金融卡扣款、青年或新戶加碼混用，保留按卡、入帳日與按月結算限制。
- 台新街口聯名卡：先分段隔離當期一般消費活動與同頁歷史、繳費活動，再交叉核對比例與交易期間。

這些數字與上限可隨符合既有語意格式的官方公告自動更新；格式缺漏、數字互相矛盾或有效期不符時回到 pending。十一者目前皆保留 `verificationRequiredReason`：實際一般消費認列、會員資格、排除交易及剩餘額度尚未完整判定，App 不得直接將公告數字當作此筆交易的確定回饋。

**已自動化的是上述十一個卡片來源指定條款數字的擷取、公告檢查、撤回無法驗證的資料與發布。尚未完成全卡庫的交易資格判定或任意新條款的語意解析。** 其他 9 個內建來源目前仍 pending。單頁雜湊也不代表其所有連結條款均已核對。自動擷取成功不等於使用者可確定取得該回饋。

## 執行與部署

此目錄內容直接放在獨立儲存庫根目錄，包含 `.github/workflows/issuer-rules.yml`。在 Settings → Pages 選 GitHub Actions，再推送至 `main` 即執行測試、抓取、產生完整資料並部署 `public/`。工作流程只發布 JSON，不會上傳 Flutter 原始碼、交易紀錄或公告全文。公告證據保存在保留 30 天的 Actions artifact。

本機執行：

```sh
python3 -m unittest discover -s tests -v
python3 pipeline.py
python3 pipeline.py --publish
```

若環境使用 macOS 系統 CA，可設 `SSL_CERT_FILE=/etc/ssl/cert.pem`。禁止停用 TLS 驗證。網頁宣告的字元編碼會納入解碼；不會用容錯解碼掩蓋條款損壞。

App 預設已設定本儲存庫的發布網址；也可用設定檔明確指定或切換來源：

```sh
flutter build ios --dart-define-from-file=config/reward_feed.json
```

現有已安裝的 App 不會因 GitHub 部署自行取得程式變更，必須先重新建置與安裝。App 相機頁啟動約三秒後依自動更新設定下載；關閉 App 時不執行同步。

## 已核對規則

`approved.json` 的每項包含 `sourceSha256` 及完整 `rule`。官方 URL 必須完全相同，文字雜湊必須一致，規則日期必須尚未過期。完整記錄需明確包含資格、方案、特店規則、平台限制與日期欄位；明確 null 用於清除上一版本限制。

格式驗證不代表銀行條款或交易資格已驗證。無法完整表達的資格，必須提供 `verificationRequiredReason` 使 App 停止精確試算。具上限規則必須同時指定額度池、週期、上限作用範圍。不要把廣告最高百分比直接視為平台全部交易回饋。

## 中信條件式試算

新版 App 可在中信信用卡與簽帳金融卡項目開啟「依條件試算」。輸入實際新臺幣刷卡淨額，逐項勾選本次有效會員綁定、一般消費與非分期假設後，以十進位精確運算逐筆四捨五入至整數點。不把多筆消費合併取整。

假設僅保存在當次對話框，不會修改持久資格、銀行設定或正常付款推薦。條款更新時清除舊假設；公告有效期或整份資料有效期任一到期都停止試算。正常掃描推薦仍保持待確認。

`calculation_approvals.json` 列出已核對、可發布條件式基本方案的公告 SHA-256（含既有中信描述與新版 assessmentProfiles）。只有擷取內容與已核對版本完全一致才發布 `issuerTerms` 計算描述。銀行改變公告時，數字觀測仍可更新，但條件式試算會先撤回直到重新核對。不能宣稱任意新條款都已能自動套用正確計算。

## 待核對原因與活動額滿

來源未能完整讀取、未公布可驗證有效期、條件未建模或特定活動已額滿時，不會為湊齊全卡庫而產生數值規則。pending_status.py 將原因列入版本化快照，新版 App 會顯示；原因隨快照過期，不會把舊額滿狀態永久沿用。目前悠遊付日常採買活動官方已標示額滿，僅撤回此活動，未宣稱其他悠遊付活動均額滿。帳戶類活動尚未形成可通用的計算模型；一個活動頁並不涵蓋該平台全部優惠。

## 結構化條件與基本方案

`assessmentProfiles` 將全部 20 個來源分成公告可讀性、條件分類、已建模範圍與待補資料；每個條件標明使用者資格、交易資料、銀行認列或額度。這是條件清單，並不宣稱已完成全部活動。`fullCardCoverage` 此版本一律 false，發布狀態明列 fullyModeledCardCount=0。

九個來源有經來源 SHA 綁定的一般基本方案條件式試算：中信信用卡／簽帳卡、台新 Richart、街口聯名卡、玉山 U Bear 、Unicard 、Costco 店外、富邦 J Points 國內與 CUBE 固定回饋國內方案。U Bear、Unicard 依電子帳單／成功自扣的三態輸入選擇基本回饋分支；尚未確認不得視為 false 或 true。這九個模型都不含全部加碼，不能把基本方案金額當作最終總回饋，也不會解除原有付款推薦的未知資格限制。

`calculation_approvals.json` 現在同時供既有中信 `issuerTerms` 與上述基本方案使用。頁面雜湊變更會撤回數字試算，但可保留尚能被既有解析器交叉核對的公告數字。額度、繳費、指定訂閱、新戶、旅遊、運動、方案切換、月底選擇及總量額滿等尚未完整建模的部分明列在 unmodeledBenefits。這些限制不是使用者勾選即可自動轉為完整規則。

三個其他來源目前僅支持條件式「名目基本比例」：聯邦吉鶴、Richart Mastercard 簽帳卡、永豐 SPORT。這些模型的 rounding 明列 notModeled，永遠不輸出確定回饋金額；富邦 J Cash、其他通路與所有加碼仍列為未涵蓋。不得將 nominalRate 欄位當作有效實得率或直接乘金額。

Costco 店外基本回饋已再核對官方《好多金回饋辦法》PDF，可在使用者明示符合會員、繳款、排除項目與請款條件後，逐筆四捨五入試算好多金。這不是現金，也不包含店內／加油／交通活動。主公告與補充 PDF 任一改變或無法取得時，都撤回該金額試算。來源 SHA 為主公告與補充文件雜湊組成的版本指紋；支持文件只儲存雜湊與來源網址，不將完整 PDF 發布到網站。

目前累計 9 個基本金額模型、3 個僅名目比例模型、8 個來源尚無可用模型。任何一類都不是「整張卡所有優惠已完整建模」；完整卡片模型數仍為 0。

目前金額模型限定新消費且無入帳後退款、退稅或調整。退款不等於將原消費淨額重新乘回饋率，原回饋取整、沖回與額度回補尚需獨立建模；使用者未確認此範圍時不顯示金額。

富邦 J Points 國內模型逐筆無條件捨去，持續符合自扣／電子帳單資格為 1%，持續不符合為 0.5%。官方資格生效時點有不同敘述，因此要求自消費日至入帳、回饋計算及結帳日狀態一致；有異動時不提供金額。J Cash、海外與加碼不在此模型範圍。SPORT 名目比例另要求 DACARD 註冊、運動資料串接與更新，未知或不符合時不得產出比例。

CUBE 已改以官方 AEM model JSON 的公開正文監測（非搜尋快取），正文解析排除腳本與網址等非條款內容，但整份結構資料另納入版本指紋，未知欄位有變更也會撤回公式。僅發布固定回饋方案的國內一般消費（不含保費、分期）1.2% 小樹點，逐筆四捨五入，另需使用者確認授權日方案及本筆全部金額均在適用認列限額內。一般 0.3%、其他方案／指定通路、海外與優惠券尚未形成完整模型；未符合固定方案不表示整張卡零回饋。App 連結仍開啟可閱讀的官方頁面，status 的來源網址保留實際擷取 JSON。

## 支付 App 活動與扣款來源

另以 walletCampaigns 發布四項條件式定額／任務獎勵，與九項發卡行基本回饋公式分開：全支付基金綁定及配息兩項每月任務、元大帳戶悠遊付學費活動、王道新戶 iPASS MONEY 簽帳金融卡三筆任務。三個官方來源皆須完整快照雜湊核准；內容變更、逾期、擷取失敗或明確額滿時撤回。

模型區分信用卡、簽帳金融卡卡號、連結銀行帳戶直接扣款、錢包餘額。現有四項都限消費，不把儲值動作當消費，也不自動與卡片或其他活動疊加。使用者須確認新戶、登錄、前月條件、名額及未領取狀態；跨日及公告更新後須重新確認。全平台所有活動仍未完整涵蓋。

## 逐項資格稽核

`eligibility-audit.json` 與 rules.json 使用相同資料有效期，列出全部 20 個來源的計算模型狀態、完整來源 SHA、每項資格由誰提供、尚未建模的規則，以及已發布支付活動的必填條件。所有交易實際資格均維持未驗證，不把來源可讀、公式存在或測試通過等同個人獲獎資格。缺少任何來源的分類時停止產生稽核表。

已修復 CUBE 簽帳金融卡的官方 AEM 內容來源；該卡與 CUBE 信用卡依 URL 和標題分開驗證，仍不直接套用信用卡取整或累積辦法。
